# Text-owned expert-exchange clock (r1)

ExLlamaV3 overlay on the served image. The CPU expert exchange of [`docker/cheapswap-r3/`](../cheapswap-r3/) (`EXL3_MOE_CPU_SWAP=1`, mode `exchange`, policy `histogram`, cadence `exact`) counts every routed pick of every split MoE layer into that layer's histogram, and decides an exchange sweep every 64 invocations of one module, the clock owner. In the base code the owner is entry 0 of the shared registry of split modules. On GLM-5.3-Flash the MTP draft model registers first, so entry 0 is the MTP layer (`model.language_model.layers.45.mlp`), and with `EXL3_MTP_MAX_BATCH=1` that layer does not run while two or more requests are active: at 2 to 4 streams the histograms fill and no sweep runs. R967 (2026-10-10, served configuration with `EXL3_MOE_CPU_SWAP_DEBUG=1`, results `2026-10-10-r967-glm53-swap-clock-114438`) logged 0 sweeps during a 4-stream round on a fresh boot (76.7 tok/s summed), 113 during the ten single-stream requests that followed, and 0 during the next 4-stream round (94.2 tok/s summed).

`EXL3_MOE_CPU_SWAP_TEXT_CLOCK=1` (default 0) gives the clock to the first registered module whose `cpu_component` is `text` (layer 3 on this model) and falls back to entry 0 while only the draft model is loaded. The tick gate in `block_sparse_mlp_cpu.py` and the counter reset in `moe_exchange.run_sweep()` use the same owner. With the flag on, the import raises `ValueError` unless mode, policy and cadence are `exchange`, `histogram` and `exact`; each registration logs a `[SWAP-OWNER]` line, and with `EXL3_MOE_CPU_SWAP_DEBUG` set `[SWAP-CLOCK]` lines count the owner's ticks and the sweeps. With the flag off the owner is entry 0 as before. The sweep itself (layer fences, transactions, the global budget of 64 pairs, the floor and hysteresis thresholds) is unchanged; the flag changes when sweeps run, not what they do.

- `textclock.patch`: the change against the base image's `exllamav3/modules/block_sparse_mlp_cpu.py` and `exllamav3/model/moe_exchange.py` (`patch -p1` from the package root of `exllamav3`); `textclock/` holds the two patched files, which are the build inputs.
- `Dockerfile`: copies the two files, checks the base files' SHA-256 before replacing them and the patched files' after, imports both modules with the flag on and asserts `TEXT_CLOCK_PATCH_VERSION == 1`. The flag stays off in the image; the launcher passes it through `EXL3_EXTRA`. The package's own notes call this file `Dockerfile.textclock`.
- `test_textclock.py`: 11 tests that run the complete patched modules with Torch and the native extension stubbed (MTP-first and text-first registries, flag off and default, fallback while only the draft is loaded, registry replacement, the first sweep at invocation 65 and one sweep per 64 invocations after it, the reset of the same owner, capture, validation, the startup and debug lines), and 10 mutations of the patch, each caught (`CPU-TESTS.txt`). The flag-off test compares traces and logs with the base files, which it reads from `../src/exllamav3/modules/block_sparse_mlp_cpu.py` and `../src/exllamav3/model/moe_exchange.py`; this package does not ship them, and their SHA-256 are in the `Dockerfile`.
- `test_gpu_unit.py`: 4 tests of the R968 driver and its summary with a stubbed launcher, probe and Docker. It expects the layout the driver ran from: `r968-glm53-textclock.sh`, `textclock_summary.py` and `glm_arms.sh` beside it and the daily environment in `../ref/glm-daily.env`. The driver and the summary are [`scripts/r968-glm53-textclock.sh`](../../scripts/r968-glm53-textclock.sh) and [`scripts/textclock_summary.py`](../../scripts/textclock_summary.py).
- `BRIEF.md`, `ANALYSIS.md`: the first round, a reading of the exchange code that located the clock owner (section 4.1) and proposed the flag (section 5). `BRIEF-r2.md`, `CHANGES.md`: the second round, the patch, the tests and the GPU unit. `REVIEW-r2.md`: the review before the GPU run; its three blocking findings (html requests are forced to 2,048 tokens, greedy fingerprints differ between boots of one image under the exchange, the unit's runtime cap) were fixed in the summary and the driver header before R968 ran. These files are kept as delivered.
- `SHA256SUMS`: every file of the package except this README.

Build from the repository root, on the image with the draft chunk bound ([`docker/draftchunk-r1/`](../draftchunk-r1/)); the build context is this directory:

```sh
docker build --pull=false --network=none \
  --build-arg BASE=tabbyapi:cheapswap-r3-agent-r2_mtpfast1_overhead-r2_splitdev2_ring3_livemetrics2_draftchunk1 \
  -f docker/textclock-r1/Dockerfile \
  -t tabbyapi:cheapswap-r3-agent-r2_mtpfast1_overhead-r2_splitdev2_ring3_livemetrics2_draftchunk1_textclock1 docker/textclock-r1
```

Measured on 2026-10-10 (R968, results `2026-10-10-r968-glm53-textclock-131424`, write-up [`bench/results/r968-glm53-textclock.md`](../../bench/results/r968-glm53-textclock.md)): with the flag on, the last `[SWAP-OWNER]` line names `model.language_model.layers.3.mlp component=text modules=43`, and one 4-stream round on a fresh debug boot logged 16 sweeps (326 swaps). Four fresh boots in the order A1 B1 B2 A2, A the image without the overlay and B this image with the flag on: the 4-stream sum on a fresh boot 84.1 and 85.6 against 77.3 and 75.8 tok/s (+10.9 % on the medians), after ten single-stream requests 96.7 and 96.2 against 94.4 and 90.1 (+4.6 %, +2.2 % against A1 alone), and the median single-stream rate 64.1 and 64.7 against 65.7 and 65.6 tok/s (−1.9 %, −1.2 % without one A2 request whose draft acceptance fell to 0.64). Single-stream decode is the shape most real traffic has; its −1.2 to −1.9 % is inside the per-arm drift of about 2.7 % measured on this stack in R961b, B is below A in 8 of the 10 (kind, run) cells, and the cause is not measured.
